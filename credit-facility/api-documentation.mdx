# Credit Facility (CF) Module - API Documentation

## 📋 Overview

The Credit Facility (CF) Module provides a comprehensive API for managing credit facility operations including Term Sheets, Master Commitments, and Funding Requests.

**Base URL:** `/cf/`

## 📋 DocuSign Integration

The Credit Facility module integrates with DocuSign for electronic signatures and status changes:

### **Master Commitment DocuSign**
- **Trigger:** When master commitment status is `PendingLenderApproval`
- **Process:** Any selected lender can complete DocuSign
- **Result:** Master commitment status changes to `ACTIVE`
- **Endpoint:** `GET /docusign/signing-complete?envelopeRequest=masterCommitmentSign&envelopeId=123&masterCommitmentId=MC-123&lenderOrgId=LENDER-456`
- **Dynamic URL:** `defaultReturnUrl` includes `masterCommitmentId` and `lenderOrgId` parameters

### **Funding Request DocuSign**
- **Trigger:** When funding request status is `FAReview`
- **Process:** Facility agent completes DocuSign approval
- **Result:** Funding request status changes to `APPROVED` + Auto-generates funding notice
- **Endpoint:** `GET /docusign/signing-complete?envelopeRequest=fundingRequestSign&envelopeId=123&fundingRequestId=FR-789`
- **Dynamic URL:** `defaultReturnUrl` includes `fundingRequestId` parameter

### **Funding Notice DocuSign**
- **Trigger:** When funding notice is auto-generated with `PENDING_ESIGN` status
- **Process:** Borrower completes DocuSign for funding notice
- **Result:** Funding notice status changes to `ESIGN_COMPLETED` + FT tokens created
- **Endpoint:** `GET /docusign/signing-complete?envelopeRequest=fundingNoticeSign&envelopeId=123&fundingNoticeId=FN-456`
- **Dynamic URL:** `defaultReturnUrl` includes `fundingNoticeId` parameter

### **Term Sheet DocuSign**
- **Trigger:** When term sheet status is `DRAFT`
- **Process:** Borrower completes DocuSign
- **Result:** Term sheet status changes to `BorrowerSigned`
- **Endpoint:** `GET /docusign/signing-complete?envelopeRequest=termSheetSign&envelopeId=123&termSheetId=TS-456`
- **Dynamic URL:** `defaultReturnUrl` includes `termSheetId` parameter

## 📋 Workflow

The Credit Facility module follows a specific workflow order:

### **1. Term Sheet (First Flow)**
- Create and manage term sheets
- Define initial terms and conditions  
- Submit for market maker review
- **Market maker approval triggers automatic master commitment creation**

### **2. Master Commitment (Second Flow)**
- **Auto-created when term sheet is approved**
- **Pre-populated with term sheet data**
- Configure collateral eligibility rules
- Manage lender groups and commitments
- Submit for lender DocuSign approval
- **Any lender's DocuSign completion activates the master commitment**

### **3. Funding Request (Third Flow)**
- Create funding requests against ACTIVE master commitments
- Submit for facility agent approval
- Facility agent review and decision process
- **Facility agent DocuSign completion triggers funding notice generation**

### **4. Funding Notice (Fourth Flow)**
- **Auto-generated when funding request is approved**
- **Pre-populated with funding request data**
- Borrower DocuSign completion creates FT tokens
- Borrower approves token transfer to make notice visible to lenders
- Individual lenders confirm fund transfers
- **Per-lender tracking instead of global status**

### Facility Setup Model Operations

#### Complete Facility Setup Model
**Endpoint:** `PUT /cf/master-commitments/:masterCommitmentId/facility-setup-model/complete`

**Description:** Mark the facility setup model as completed for an ACTIVE master commitment.

**Path Parameters:**
- `masterCommitmentId` (required): Master commitment identifier

**Request Body:** None required

**Response:**
```json
{
  "success": true,
  "message": "Facility setup model completed successfully",
  "masterCommitmentId": "MC-123",
  "facilitySetupModelStatus": "Completed"
}
```

**Business Rules:**
- Only ACTIVE master commitments can have facility setup model completed
- Can only be completed once (prevents duplicate completion)
- Updates `facilitySetupModelStatus` from 'In Progress' to 'Completed'
- Adds entry to action history

**Status Values:**
- `'In Progress'` - Facility agent working on the model (default when ACTIVE)
- `'Completed'` - Facility agent finished the model (one-time action)

**Endpoint:** `POST /cf/maploanstofacility`

**Request Body:**
```json
{
  "jobId": "JOB-20241201-1701234567",
  "selectAll": false,
  "selectedLoans": ["LOAN-001", "LOAN-002", "LOAN-003"],

}
```

```json

  "isSuccess": true,
  "message": "Pool Updated Successfully",
  "data": {
    "loansUpdated": 3,
    "previewsUpdated": 3,
    "loansProcessed": 3
  }
```

- Loans must not be already mapped to another facility
